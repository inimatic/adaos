# Product Tracks

Status: public product map for the 2027 documentation track.

AdaOS uses one shared runtime foundation. Products and solutions are packaged
experiences on top of that foundation, not separate forks of AdaOS.

## Current Public Tracks

| Track | Public maturity | User promise |
| --- | --- | --- |
| AdaOS Runtime Foundation | Implemented foundation | Run a local-first assistant environment with skills, scenarios, browser access, and hub/member nodes. |
| Media Center | Beta candidate | Use AdaOS as a private media library and playback surface without copying large media files into AdaOS storage. |
| Builder | Experimental | Turn an idea into a governed AdaOS application candidate through prototype, validation, and review. |

## Not Yet Public Stable Tracks

| Track | Current public stance |
| --- | --- |
| aResearcher | Not published as a stable 2027 offer yet. It needs effectiveness evidence and a clearer public method boundary. |
| reDevice | Not published as a stable 2027 offer yet. It needs a sharper device-owner journey and hardware/software acceptance evidence. |
| AdaOS Home, Campus, Enterprise | Deployment-profile language is useful, but the public site should not imply packaged availability before the install and support model is ready. |

## Naming Guidance

Use product names for user-facing journeys and outcomes. Use platform terms
only when a user needs to understand how AdaOS works:

- **Assistant**: the user-facing environment.
- **Hub**: the node that owns and coordinates a subnet.
- **Member**: another node joined to the subnet.
- **Application**: an installable AdaOS experience.
- **Skill**: a focused executable capability.
- **Scenario**: a multi-step flow across skills, services, people, and nodes.
